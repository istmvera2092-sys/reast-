# RESTAURANT GAME — инструкция для VS Code / AI coding agent

> **Задача для исполнителя:** создать полностью работающую браузерную мини-игру «Restaurant» по этому техническому заданию. Не ограничиваться макетом или описанием: создать файлы проекта, написать код, оформить интерфейс, проверить запуск и исправить обнаруженные ошибки.
>
> Интерфейс игры — **на английском языке**. Инструкция для разработчика — на русском.

## 1. Концепция

Это яркая интерактивная игра для детей, изучающих английский язык (уровень A1). На экране расположен уютный парижский ресторан с **двумя большими иллюстрированными меню**:

- **FOOD** — меню еды.
- **DRINKS** — меню напитков.

В верхнем углу находится дружелюбный **мультяшный официант**. Под меню по центру — большая заметная кнопка **ORDER**. Каждое нажатие создаёт **новый случайный заказ**, состоящий из нескольких блюд и одного напитка. Заказ показывается в отдельной красивой карточке с картинками и названиями на английском.

**Важно:** меню FOOD и DRINKS всегда видны. Нажатие ORDER не меняет состав меню, а только генерирует заказ из перечисленных продуктов.

## 2. Визуальный стиль

Оформление вдохновлено **атмосферой мультфильма «Рататуй»**: уютный французский ресторан, парижское бистро, выразительная доброжелательная мультяшная стилистика, красивые объёмные иллюстрации еды, ощущение тёплого ресторанного освещения.

При этом **не копировать** конкретных персонажей, кадры, логотипы или официальные изображения фильма: создать собственный оригинальный мир ресторана.

### Арт-дирекшн

- Палитра: глубокий тёмно-синий, бордовый, кремовый, приглушённый золотистый, оттенки дерева; без общего жёлтого фильтра.
- Фон: интерьер французского бистро с мягким светом, декоративными элементами и лёгкой глубиной; не перегружать игровую область.
- Две карточки-меню, напоминающие ресторанные доски или страницы изысканного меню.
- У каждого продукта должна быть **собственная узнаваемая цветная иллюстрация** (не только текст, не emoji, не пустые прямоугольники).
- Официант: оригинальный добрый персонаж в фартуке или с бабочкой, размещён в углу и не закрывает меню. Можно добавить речевой пузырь.
- Внешний вид должен быть игровым, аккуратным, ярким и хорошо читаемым на интерактивной доске/ноутбуке.
- Лёгкие анимации: появление заказа, небольшое нажатие кнопки, мягкое движение персонажа. Не злоупотреблять эффектами.

### Графические ресурсы

Если у coding agent есть доступ к генерации изображений — **сгенерировать оригинальные иллюстрации** для персонажа, фонового оформления и карточек еды/напитков в едином стиле и сохранить их в проекте (`public/assets/`). Если инструментов генерации нет, использовать тщательно выполненные **локальные SVG-иллюстрации**. Не заменять графику emoji и не использовать битые или нестабильные внешние ссылки. Все изображения должны отображаться без интернета после установки зависимостей.

## 3. Расположение элементов на экране

**Desktop / интерактивная доска:**

1. Наверху небольшой заголовок **RESTAURANT**.
2. В одном верхнем углу — официант (примерно 15–20% ширины, не перекрывая текст).
3. В центре — две большие карточки **FOOD** и **DRINKS** рядом друг с другом.
4. Внутри каждой карточки — сетка из маленьких иллюстраций с подписями на английском.
5. Под обеими карточками, по центру — большая кнопка **ORDER**.
6. Ниже или поверх нижней части интерфейса — область **YOUR ORDER**, где отображается результат.

**Планшет / телефон:** две карточки располагаются друг под другом; кнопка и результат остаются удобными для использования. Никаких горизонтальных прокруток, обрезанных названий или элементов поверх других.

## 5. Механика кнопки ORDER

### При загрузке

- Видны оба меню со **всеми** продуктами и напитками.
- Кнопка ORDER активна.
- Область заказа показывает дружелюбную подсказку: **"Press ORDER to get your meal!"**.

### При нажатии ORDER

1. Случайным образом выбрать **от 2 до 4 разных позиций FOOD**.
2. Случайным образом выбрать **ровно 1 напиток DRINKS**.
3. Не допускать повторов одного продукта **внутри одного заказа**.
4. Новый заказ по возможности должен отличаться от предыдущего (перегенерировать, если случайно вышел полностью идентичный).
5. В карточке **YOUR ORDER** показать иллюстрации всех выбранных позиций и соответствующие английские названия.
6. Вывести короткую фразу от официанта: **"Here's your order!"**.
7. При следующем нажатии ORDER заменить текущий заказ новым, без перезагрузки страницы.

### Дополнительно к выборке

- `ketchup` и `mayonnaise` могут попадать в заказ как обычные позиции из FOOD: **не исключать их из алгоритма**.
- Случайность должна быть реальной, а не циклом из 3–4 заранее заданных комбинаций.
- Использовать `Math.random()` и корректное перемешивание (например, Fisher–Yates).
- Нужны аккуратные переходы, но без задержек, мешающих повторным нажатиям.

## 6. Карточка заказа

Оформить как ресторанный поднос, чек или заказную карточку:

**YOUR ORDER**

- [изображение] `salad`
- [изображение] `waffles`
- [изображение] `water`

Это **только пример**. Состав заказа всегда случайный по правилам раздела 5.

Карточка должна легко читаться на большом экране. Не показывать технические ID, JSON, отладочную информацию или заглушки.

## 7. Требования к реализации

- Стек: **Vite + React + TypeScript + CSS** (без обязательного сервера и базы данных).
- Удобная компонентная структура: например, `App`, `MenuPanel`, `MenuItem`, `Waiter`, `OrderButton`, `OrderResult`.
- Справочники еды и напитков хранить отдельно от JSX (`src/data/menu.ts`).
- Вынести функцию генерации заказа в чистую тестируемую функцию (`src/utils/generateOrder.ts`).
- Для каждого изображения предусмотреть понятный `alt`.
- Кнопка ORDER должна работать мышью, касанием и с клавиатуры.
- Размеры текста достаточные для детской аудитории; контраст между подписью и фоном хороший.
- Эффекты не должны ломать работу на слабом компьютере; учитывать `prefers-reduced-motion`.
- Не использовать платные API, API-ключи, авторизацию и запросы на внешние сервисы для работы игры.
- Страница адаптирована под экран 1920×1080 и 1366×768, а также под планшет.

## 8. Что coding agent должен сделать самостоятельно

1. Если в текущей папке нет проекта, создать его на Vite + React + TypeScript; если проект уже есть — встроить игру без удаления посторонних рабочих файлов.
2. Написать полностью работающие компоненты и стили.
3. Создать / подготовить локальную графику в едином стиле и подставить корректные пути ко всем **31** позициям меню (23 FOOD + 8 DRINKS), а также к официанту и фону.
4. Убедиться, что **каждый** продукт виден на меню и имеет правильную английскую подпись.
5. Реализовать генерацию заказа и его обновление по кнопке.
6. Проверить работу и отсутствие ошибок в консоли, пропавших картинок и переполнения разметки.
7. Выполнить `npm install`, `npm run build` и устранить ошибки сборки.
8. Написать в `README.md`, как запускать игру командами `npm install` и `npm run dev`.
9. В конце сообщить, какие файлы созданы и как открыть готовую игру.

- [ ] Все продукты имеют различимые иллюстрации, а не emoji или текстовые заглушки.
- [ ] Оригинальный официант находится в углу и не мешает меню.
- [ ] Кнопка ORDER расположена под меню и заметна.
- [ ] ORDER создаёт случайный набор из 2–4 уникальных позиций FOOD и 1 напитка.
- [ ] Результат содержит картинки и английские названия.
- [ ] Повторное нажатие создаёт новый заказ, не перезагружая страницу.
- [ ] Общая стилистика — атмосферное мультяшное парижское бистро.
- [ ] Работает на компьютере, планшете и интерактивной доске.
- [ ] `npm run build` проходит успешно.

**Приоритет:** сначала рабочая механика и полное совпадение списка слов, затем качество иллюстраций и анимации. Не завершать задачу на этапе прототипа: нужен законченный игровой экран.
